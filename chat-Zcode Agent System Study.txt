## 2. The Actual Internals

ZCode is explicitly defined as a "coding agent harness" rather than an IDE extension . It is divided into clients, backend services, shared UI, and the Agent CLI/runtime source code.

### 2.1 Repository Layout & Process Boundaries
The repository is strictly modular, governed by an `architecture-policy.yaml` that enforces rigid module boundaries, maximum file line counts (400), and contract line limits (300) to prevent architectural drift .
*   **`apps/zcode-cli`**: The core Agent CLI, Terminal UI (TUI), runtime, and tooling .
*   **`packages/desktop`**: Electron Main, Host, and Renderer .
*   **`packages/server`**: HTTP/WebSocket backend for remote connections and Web mode .
*   **`packages/client` & `packages/shared`**: Agent Client SDK, RPC framework, and the strict `zcode-protocol` .
*   **`packages/services` & `packages/storage`**: Business logic and persistence .
*   **`packages/provider`**: Model provider adapters (likely including Z.ai's GLM-5.3) .

### 2.2 Agent Runtime & Communication Protocol
The Desktop app communicates with the Agent runtime via **stdio** using the strictly typed `zcode-protocol` .
*   **Host & Workspace Isolation:** The system uses `workspaceIdentity` for identity isolation and `workspacePath` for file operations . Remote connections pass these identities end-to-end to prevent cross-workspace contamination .
*   **Concurrency Control (`CommandInbox`):** Incoming "busy/running" commands and inputs are serially admitted through the CLI/runtime `CommandInbox` . The UI (Renderer) only retains drafts and optimistic overlays, while the Host owner/lease handles the actual routing .
*   **Mobile & Remote Parity:** Mobile remote control connects to the existing desktop Host attachment, reusing the exact same session runtime instead of spinning up a separate agent .

### 2.3 The Agent Lifecycle & Workflow System
Instead of a simple linear ReAct loop, ZCode employs a **Dynamic Workflow Engine**.
*   **Workflows as First-Class Objects:** The agent can generate, modify, restart, and parallelize workflows .
*   **Concurrency & State:** Workflows have adjustable concurrency limits and real-time status displays .
*   **Context Management:** The system actively manages how workflow scripts are submitted to the LLM, specifically reducing token consumption to avoid context overflow during long-horizon tasks .

### 2.4 Tool System, Skills, and Plugins (Extensibility)
ZCode relies heavily on a Plugin and Skill ecosystem (managed via the `zcode-plugins` marketplace). The Agent runtime reads an `AGENTS.md` file and discovers capabilities dynamically.
*   **Skills (`SKILL.md`):** Plugins define skills with precise `name` and `description` frontmatter so the LLM knows exactly *when* to invoke them .
*   **Sub-Agents:** Plugins can define sub-agents (`agents/*.md`) with specific system prompts, enabling a multi-agent orchestration architecture .
*   **MCP (Model Context Protocol):** The runtime auto-connects to workspace-level MCP servers. It executes configured commands, manages environment variables, and handles OAuth/authentication headers to connect to external services .
*   **Self-Maintenance:** Remarkably, the repository includes `.agents/skills/architecture-governance/SKILL.md`, meaning the ZCode agent is explicitly prompted and skilled to maintain, lint, and govern its own source code architecture .

**The `budget-checker.mjs` Logic:**
1.  ZCode passes the tool input (the generated workflow plan or sub-agent prompt) to your script via `stdin` .
2.  Your script counts the tokens in the input and estimates the execution cost based on the current model's pricing.
3.  It queries the MCP server for the "Remaining Session Budget."
4.  **If the cost is too high**, the script returns a `permissionDecision: "deny"` with a `permissionDecisionReason` : 
    * *"BLOCKED: This autogenerated workflow requires ~150k tokens. Session budget remaining is 50k tokens. Simplify the workflow into single-agent steps or reduce context size."*
5.  **If the cost is acceptable**, it returns `permissionDecision: "allow"` and deducts the estimated cost from the budget.

This effectively forces the LLM to "look at the price tag" before executing autogenerated multi-agent pipelines.

---

### Implementation Blueprint 3: Persistent Usage Tracking via MCP

To make the budget tracking persistent across long sessions, you will bundle an **MCP Server** with your plugin .

*   **The Server:** A lightweight Node.js process that maintains a JSON ledger of token usage per worker agent (`orchestrator`, `frontend-worker`, etc.).
*   **The Tools:** It exposes tools like `record_token_usage(agent_id, tokens)` and `get_remaining_budget()`.
*   **Integration:** Your `PostToolUse` hook automatically calls `record_token_usage` every time a sub-agent completes a task, updating the ledger in real-time.

## 2.4 Token Estimation Algorithm (COMPLEX LOGIC)

This is the most critical algorithm in the system. It must be fast (< 50ms) and accurate enough to prevent budget overruns.

```typescript
// ═══════════════════════════════════════════════════════════
// FILE: plugins/budget-governor/src/estimator.ts
// ═══════════════════════════════════════════════════════════

/**
 * TOKEN ESTIMATION ENGINE
 * 
 * Four-tier estimation strategy, selected by accuracy/speed tradeoff:
 * 
 * Tier 1: Character Heuristic (fastest, ~10ms, ±30% accuracy)
 *   - chars / 4 ≈ tokens (English text)
 *   - chars / 2 ≈ tokens (CJK text)
 *   - Used for: initial budget checks, high-frequency operations
 * 
 * Tier 2: Tiktoken Exact Count (medium, ~30ms, ±5% accuracy)
 *   - Actual tokenizer count for the target model
 *   - Used for: workflow plan validation, sub-agent spawn decisions
 * 
 * Tier 3: Historical Average (medium, ~5ms, ±15% accuracy)
 *   - Mean tokens from last N similar operations
 *   - Used for: recurring operations, calibrated estimates
 * 
 * Tier 4: LLM Prediction (slowest, ~500ms, ±10% accuracy)
 *   - Ask a cheap model to predict output length
 *   - Used for: novel operations, high-stakes decisions
 */

class TokenEstimator {
  private history: Map<string, number[]>;  // operationType → token counts
  private pricing: Map<string, ModelPricing>;
  private calibrationFactors: Map<string, number>;  // operationType → correction multiplier

  /**
   * MAIN ESTIMATION ENTRY POINT
   * 
   * Decision tree for selecting estimation tier:
   * 
   * IF operation is a tool_call with known output format:
   *   → Tier 3 (historical average)
   * ELSE IF operation is a workflow_step with defined schema:
   *   → Tier 2 (tiktoken on input) + Tier 3 (historical output)
   * ELSE IF operation is a subagent_spawn:
   *   → Tier 2 (tiktoken on prompt) + Tier 4 (LLM predict output)
   * ELSE IF operation is a novel model_query:
   *   → Tier 1 (heuristic) for fast check
   *   → IF estimated cost > 50% of remaining budget:
   *       → Tier 4 (LLM prediction) for accuracy
   * ELSE:
   *   → Tier 1 (heuristic)
   */
  estimate(
    operation: Operation,
    context: EstimationContext,
    requiredAccuracy: 'fast' | 'balanced' | 'precise'
  ): CostEstimate {
    
    const tier = this.selectTier(operation, context, requiredAccuracy);
    
    switch (tier) {
      case 1: return this.estimateTier1(operation, context);
      case 2: return this.estimateTier2(operation, context);
      case 3: return this.estimateTier3(operation, context);
      case 4: return this.estimateTier4(operation, context);
    }
  }

  /**
   * TIER 1: CHARACTER HEURISTIC
   * 
   * Algorithm:
   * 1. Count characters in input text
   * 2. Detect language (CJK vs Latin vs mixed)
   * 3. Apply language-specific divisor
   * 4. Apply calibration factor from historical data
   * 5. Estimate output tokens using operation-type multiplier
   * 
   * Calibration factors (updated from actual usage):
   *   code_generation: 1.4 (code is denser than prose)
   *   code_review: 0.8 (reviews are shorter than generation)
   *   refactoring: 1.2 (refactors produce moderate output)
   *   documentation: 1.6 (docs are verbose)
   *   debugging: 0.6 (debug output is concise)
   */
  private estimateTier1(op: Operation, ctx: EstimationContext): CostEstimate {
    const inputChars = this.countChars(op.inputText);
    const languageRatio = this.detectLanguageRatio(op.inputText);
    
    // Weighted divisor: Latin ≈ 4 chars/token, CJK ≈ 2 chars/token
    const divisor = 4 * (1 - languageRatio.cjk) + 2 * languageRatio.cjk;
    
    let inputTokens = Math.ceil(inputChars / divisor);
    
    // Apply calibration factor
    const calFactor = this.calibrationFactors.get(op.type) ?? 1.0;
    inputTokens = Math.ceil(inputTokens * calFactor);
    
    // Estimate output tokens based on operation type
    const outputMultiplier = this.getOutputMultiplier(op.type);
    const outputTokens = Math.ceil(inputTokens * outputMultiplier);
    
    const cost = this.calculateCost(op.modelId, inputTokens, outputTokens);
    
    return {
      operationId: op.id,
      operationType: op.type,
      modelId: op.modelId,
      estimatedInputTokens: inputTokens,
      estimatedOutputTokens: outputTokens,
      estimatedCostUsd: cost,
      confidenceLevel: 'low',
      estimationMethod: 'char_heuristic',
      timestamp: Date.now()
    };
  }

  /**
   * TIER 2: TIKTOKEN EXACT COUNT
   * 
   * Algorithm:
   * 1. Load tokenizer for target model
   * 2. Encode input text → exact token count
   * 3. For output estimation:
   *    a. If operation has a defined output schema → estimate from schema
   *    b. If operation is code generation → input_tokens * 1.3
   *    c. If operation is analysis → input_tokens * 0.4
   *    d. Otherwise → use historical average for this operation type
   * 4. Add system prompt overhead (typically 800-2000 tokens)
   * 5. Add tool schema overhead (typically 200-500 tokens per tool)
   */
  private estimateTier2(op: Operation, ctx: EstimationContext): CostEstimate {
    const tokenizer = this.getTokenizer(op.modelId);
    
    // Exact input count
    const systemPromptTokens = tokenizer.encode(ctx.systemPrompt).length;
    const toolSchemaTokens = ctx.tools.reduce(
      (sum, tool) => sum + tokenizer.encode(JSON.stringify(tool.schema)).length, 0
    );
    const userMessageTokens = tokenizer.encode(op.inputText).length;
    const contextTokens = ctx.relevantContext
      ? tokenizer.encode(ctx.relevantContext).length
      : 0;
    
    const inputTokens = systemPromptTokens + toolSchemaTokens + 
                        userMessageTokens + contextTokens;
    
    // Output estimation
    let outputTokens: number;
    if (op.outputSchema) {
      outputTokens = this.estimateFromSchema(op.outputSchema, tokenizer);
    } else {
      const multiplier = this.getOutputMultiplier(op.type);
      outputTokens = Math.ceil(userMessageTokens * multiplier);
    }
    
    const cost = this.calculateCost(op.modelId, inputTokens, outputTokens);
    
    return {
      operationId: op.id,
      operationType: op.type,
      modelId: op.modelId,
      estimatedInputTokens: inputTokens,
      estimatedOutputTokens: outputTokens,
      estimatedCostUsd: cost,
      confidenceLevel: 'medium',
      estimationMethod: 'tiktoken',
      timestamp: Date.now()
    };
  }

  /**
   * TIER 3: HISTORICAL AVERAGE
   * 
   * Algorithm:
   * 1. Look up last N (default 20) operations of the same type
   * 2. Filter to same model (or similar model family)
   * 3. Calculate: mean, median, p95 of token counts
   * 4. Use p95 for budget reservation (conservative)
   * 5. Use median for display (realistic)
   * 6. If fewer than 5 historical samples → fall back to Tier 1
   * 
   * Exponential decay weighting:
   *   weight(i) = 0.95^i  (most recent = highest weight)
   *   This ensures the estimator adapts to model/prompt changes
   */
  private estimateTier3(op: Operation, ctx: EstimationContext): CostEstimate {
    const history = this.history.get(op.type) ?? [];
    
    if (history.length < 5) {
      return this.estimateTier1(op, ctx);  // Fallback
    }
    
    // Exponential decay weighting
    const weighted = history.map((tokens, i) => ({
      tokens,
      weight: Math.pow(0.95, i)
    }));
    
    const totalWeight = weighted.reduce((s, w) => s + w.weight, 0);
    const weightedMean = weighted.reduce((s, w) => s + w.tokens * w.weight, 0) / totalWeight;
    
    // Sort for percentile calculation
    const sorted = [...history].sort((a, b) => a - b);
    const p95Index = Math.ceil(sorted.length * 0.95) - 1;
    const p95 = sorted[p95Index];
    const median = sorted[Math.floor(sorted.length / 2)];
    
    // Use p95 for budget reservation, median for display
    const inputTokens = Math.ceil(p95 * 0.6);   // 60% of total is typically input
    const outputTokens = Math.ceil(p95 * 0.4);   // 40% is typically output
    
    const cost = this.calculateCost(op.modelId, inputTokens, outputTokens);
    
    return {
      operationId: op.id,
      operationType: op.type,
      modelId: op.modelId,
      estimatedInputTokens: inputTokens,
      estimatedOutputTokens: outputTokens,
      estimatedCostUsd: cost,
      confidenceLevel: 'high',
      estimationMethod: 'historical_average',
      timestamp: Date.now()
    };
  }

  /**
   * TIER 4: LLM PREDICTION
   * 
   * Algorithm:
   * 1. Construct a meta-prompt asking a cheap model to predict output length
   * 2. Include: operation type, input summary (first 500 chars), 
   *    historical averages, output schema if available
   * 3. Parse the prediction (expected output tokens ± range)
   * 4. Use the upper bound for budget reservation
   * 5. Cache the prediction for similar future operations
   * 
   * Meta-prompt template:
   * "Given this operation type: {type}
   *  Input summary: {first500chars}
   *  Historical average output: {histAvg} tokens
   *  Output schema: {schema or 'free-form'}
   *  
   *  Predict the output token count. Respond with JSON:
   *  {predicted: number, lowerBound: number, upperBound: number}"
   * 
   * Cost of Tier 4 itself: ~200 tokens input, ~50 tokens output
   * Only invoke when: estimated cost > 30% of remaining budget
   */
  private async estimateTier4(op: Operation, ctx: EstimationContext): Promise<CostEstimate> {
    const metaPrompt = this.buildMetaPrompt(op, ctx);
    
    // Use cheapest available model for prediction
    const prediction = await this.callModel('cheapest', metaPrompt);
    const parsed = JSON.parse(prediction);
    
    const outputTokens = parsed.upperBound;  // Conservative
    const inputTokens = this.estimateTier2(op, ctx).estimatedInputTokens;
    
    const cost = this.calculateCost(op.modelId, inputTokens, outputTokens);
    
    return {
      operationId: op.id,
      operationType: op.type,
      modelId: op.modelId,
      estimatedInputTokens: inputTokens,
      estimatedOutputTokens: outputTokens,
      estimatedCostUsd: cost,
      confidenceLevel: 'medium',
      estimationMethod: 'llm_prediction',
      timestamp: Date.now()
    };
  }

  /**
   * CALIBRATION LOOP
   * 
   * After every operation completes, update calibration:
   * 
   * 1. Compare estimated vs actual tokens
   * 2. Calculate variance: (actual - estimated) / estimated
   * 3. If |variance| > 20% for 3 consecutive operations of same type:
   *    → Adjust calibration factor: newFactor = oldFactor * (actual/estimated)
   *    → Clamp factor to [0.5, 2.0] to prevent runaway
   * 4. Append actual token count to history (keep last 100)
   * 5. If variance > 50% → flag for human review
   */
  calibrate(entry: LedgerEntry): void {
    const variance = entry.variancePercent;
    
    // Update history
    const hist = this.history.get(entry.operationId) ?? [];
    hist.unshift(entry.actualInputTokens + entry.actualOutputTokens);
    if (hist.length > 100) hist.pop();
    this.history.set(entry.operationId, hist);
    
    // Adjust calibration factor
    if (Math.abs(variance) > 20) {
      const current = this.calibrationFactors.get(entry.operationId) ?? 1.0;
      const adjustment = entry.actualInputTokens / entry.estimatedInputTokens;
      const newFactor = Math.max(0.5, Math.min(2.0, current * adjustment));
      this.calibrationFactors.set(entry.operationId, newFactor);
    }
  }

  private calculateCost(modelId: string, input: number, output: number): number {
    const pricing = this.pricing.get(modelId);
    if (!pricing) return 0;
    return (input / 1_000_000 * pricing.inputPerMillion) +
           (output / 1_000_000 * pricing.outputPerMillion);
  }

  private getOutputMultiplier(type: string): number {
    const multipliers: Record<string, number> = {
      'code_generation': 1.4,
      'code_review': 0.8,
      'refactoring': 1.2,
      'documentation': 1.6,
      'debugging': 0.6,
      'testing': 1.1,
      'architecture': 1.3,
      'workflow_step': 1.0,
      'subagent_spawn': 0.9,
      'tool_call': 0.3,
    };
    return multipliers[type] ?? 1.0;
  }
}
```

```typescript
// ═══════════════════════════════════════════════════════════
// FILE: plugins/budget-governor/hooks/budget-checker.mjs
// ═══════════════════════════════════════════════════════════

/**
 * EXECUTION FLOW:
 * 
 * 1. ZCode runtime calls this hook via stdin (JSON)
 * 2. Parse the tool_name and tool_input
 * 3. IF tool_name matches 'Agent|Task|Workflow|delegate_task':
 *    a. Estimate cost of the operation
 *    b. Query Budget Ledger MCP for remaining budget
 *    c. Apply decision matrix (see below)
 *    d. Return JSON response to stdout
 * 4. ELSE: pass through (allow)
 * 
 * DECISION MATRIX:
 * 
 * ┌─────────────────────────────────────────────────────────────┐
 * │ estimated_cost / remaining_budget │ Decision                │
 * ├───────────────────────────────────┼─────────────────────────┤
 * │ < 10%                             │ ALLOW                   │
 * │ 10% - 30%                         │ ALLOW + warn            │
 * │ 30% - 60%                         │ SIMPLIFY (suggest alt)  │
 * │ 60% - 90%                         │ ESCALATE_TO_HUMAN       │
 * │ > 90%                             │ DENY                    │
 * │ > 100%                            │ DENY (hard block)       │
 * └───────────────────────────────────┴─────────────────────────┘
 * 
 * OVERRIDE RULES:
 * - If user has set ZCODE_BUDGET_OVERRIDE=true → always ALLOW
 * - If operation is a safety/security check → always ALLOW
 * - If operation is a rollback/undo → always ALLOW
 */

import { readFileSync } from 'fs';
import { join } from 'path';

// Read stdin (ZCode hook protocol)
let raw = '';
process.stdin.setEncoding('utf8');
for await (const chunk of process.stdin) raw += chunk;

const input = JSON.parse(raw);
const { tool_name, tool_input, session_id } = input;

// Only intercept workflow/agent operations
const INTERCEPTED_TOOLS = /^(Agent|Task|Workflow|delegate_task|spawn_worker)$/;

if (!INTERCEPTED_TOOLS.test(tool_name)) {
  // Pass through — not a budgeted operation
  process.stdout.write('{}');
  process.exit(0);
}

// ─── ESTIMATE COST ───────────────────────────────────────────
const estimator = new TokenEstimator();
const estimate = estimator.estimate(
  {
    id: input.tool_use_id,
    type: tool_name === 'delegate_task' ? 'subagent_spawn' : 'workflow_step',
    modelId: tool_input.model ?? 'default',
    inputText: JSON.stringify(tool_input),
  },
  {
    systemPrompt: '',  // Not available in hook context
    tools: [],
    relevantContext: tool_input.context ?? '',
  },
  'balanced'
);

// ─── QUERY BUDGET LEDGER ─────────────────────────────────────
// Call the Budget Ledger MCP server
const budget = await queryBudgetLedger(session_id);
const remaining = budget.remainingUsd;
const ratio = estimate.estimatedCostUsd / remaining;

// ─── APPLY DECISION MATRIX ───────────────────────────────────
let decision;

if (process.env.ZCODE_BUDGET_OVERRIDE === 'true') {
  decision = { decision: 'allow', reason: 'Budget override enabled' };
} else if (isSafetyOperation(tool_input)) {
  decision = { decision: 'allow', reason: 'Safety operation — always permitted' };
} else if (ratio < 0.10) {
  decision = { decision: 'allow', reason: 'Within budget' };
} else if (ratio < 0.30) {
  decision = { 
    decision: 'allow', 
    reason: `Warning: This operation will use ${(ratio*100).toFixed(0)}% of remaining budget ($${estimate.estimatedCostUsd.toFixed(4)})` 
  };
} else if (ratio < 0.60) {
  decision = {
    decision: 'simplify',
    reason: `Operation estimated at $${estimate.estimatedCostUsd.toFixed(4)} (${(ratio*100).toFixed(0)}% of budget). Consider breaking into smaller steps.`,
    suggestedAlternative: generateSimplifiedPlan(tool_input)
  };
} else if (ratio < 0.90) {
  decision = {
    decision: 'escalate_to_human',
    reason: `Operation requires $${estimate.estimatedCostUsd.toFixed(4)} but only $${remaining.toFixed(4)} remains.`,
    requiredBudgetIncrease: estimate.estimatedCostUsd - remaining
  };
} else {
  decision = {
    decision: 'deny',
    reason: `DENIED: Estimated cost $${estimate.estimatedCostUsd.toFixed(4)} exceeds remaining budget $${remaining.toFixed(4)}. Simplify the workflow or increase budget.`
  };
}

// ─── RESERVE BUDGET (if allowed) ─────────────────────────────
if (decision.decision === 'allow') {
  await reserveBudget(session_id, estimate.estimatedCostUsd);
}

// ─── RETURN DECISION ─────────────────────────────────────────
if (decision.decision === 'deny') {
  process.stdout.write(JSON.stringify({
    hookSpecificOutput: {
      hookEventName: 'PreToolUse',
      permissionDecision: 'deny',
      permissionDecisionReason: decision.reason,
      additionalContext: `Budget Governor: ${decision.reason}`
    }
  }));
} else if (decision.decision === 'simplify') {
  process.stdout.write(JSON.stringify({
    hookSpecificOutput: {
      hookEventName: 'PreToolUse',
      permissionDecision: 'deny',
      permissionDecisionReason: decision.reason,
      additionalContext: `Budget Governor suggests: ${decision.suggestedAlternative}`
    }
  }));
} else {
  process.stdout.write(JSON.stringify({
    hookSpecificOutput: {
      hookEventName: 'PreToolUse',
      permissionDecision: 'allow',
      additionalContext: decision.reason
    }
  }));
}
```

## 3.3 Project Scanning Algorithm (COMPLEX LOGIC)

```typescript
// ═══════════════════════════════════════════════════════════
// FILE: plugins/seed-team-generator/src/scanner.ts
// ═══════════════════════════════════════════════════════════

/**
 * PROJECT SCANNING ALGORITHM
 * 
 * Input: workspace root path
 * Output: ProjectProfile
 * 
 * The scanner produces a structured fingerprint of the project
 * that drives all subsequent team derivation decisions.
 */

interface ProjectProfile {
  // Identity
  projectName: string;
  workspaceIdentity: string;
  scanTimestamp: number;
  
  // Language & Framework
  primaryLanguages: LanguageShare[];       // [{lang: 'typescript', share: 0.72}, ...]
  frameworks: FrameworkDetection[];        // [{name: 'react', confidence: 0.95}, ...]
  buildSystem: string;                     // 'pnpm' | 'npm' | 'cargo' | 'make' | ...
  packageManager: string;
  
  // Structure
  totalFiles: number;
  totalLinesOfCode: number;
  directoryDepth: number;
  moduleCount: number;
  hasMonorepo: boolean;
  workspacePackages: string[];             // For monorepos
  
  // Complexity Indicators
  complexityScore: number;                 // 0-100 composite
  hasTests: boolean;
  testCoverageEstimate: number;            // 0-1
  hasCI: boolean;
  hasDocumentation: boolean;
  hasApiLayer: boolean;
  hasDatabase: boolean;
  hasFrontend: boolean;
  hasBackend: boolean;
  hasInfrastructure: boolean;              // Docker, K8s, Terraform
  hasMobile: boolean;
  hasMLComponents: boolean;
  
  // Dependency Surface
  totalDependencies: number;
  devDependencies: number;
  hasNativeModules: boolean;
  hasExternalServices: boolean;            // API keys, OAuth configs
  securitySurface: 'low' | 'medium' | 'high';
  
  // Git & Workflow
  hasGitHistory: boolean;
  commitFrequency: 'low' | 'medium' | 'high';
  branchCount: number;
  hasOpenPRs: boolean;
  
  // Special Indicators
  hasAgentsMd: boolean;
  hasExistingTeam: boolean;                // agents/*.md already exist
  hasMcpServers: boolean;
  hasCustomSkills: boolean;
}

interface LanguageShare {
  language: string;
  share: number;          // 0.0 - 1.0
  fileCount: number;
  lineCount: number;
}

interface FrameworkDetection {
  name: string;
  confidence: number;     // 0.0 - 1.0
  evidence: string;       // What file/config triggered detection
}

class ProjectScanner {
  
  /**
   * MASTER SCAN FUNCTION
   * 
   * Execution order matters — later phases depend on earlier results:
   * 
   * 1. File tree walk (fast, no parsing)
   * 2. Manifest detection (package.json, Cargo.toml, go.mod, etc.)
   * 3. Language detection (by extension + manifest)
   * 4. Framework detection (by dependency names + config files)
   * 5. Complexity scoring (composite of all signals)
   * 6. Security surface assessment
   * 7. Existing team detection
   */
  async scan(workspaceRoot: string): Promise<ProjectProfile> {
    const profile: Partial<ProjectProfile> = {};
    
    // Phase 1: File tree walk
    const fileTree = await this.walkFileTree(workspaceRoot, {
      ignore: ['node_modules', '.git', 'dist', 'build', '.next', 'coverage', '__pycache__'],
      maxDepth: 12,
      maxFiles: 10000
    });
    
    profile.totalFiles = fileTree.length;
    profile.directoryDepth = Math.max(...fileTree.map(f => f.depth));
    
    // Phase 2: Manifest detection
    const manifests = await this.detectManifests(workspaceRoot, fileTree);
    profile.buildSystem = manifests.buildSystem;
    profile.packageManager = manifests.packageManager;
    profile.hasMonorepo = manifests.isMonorepo;
    profile.workspacePackages = manifests.workspaces;
    
    // Phase 3: Language detection
    profile.primaryLanguages = this.detectLanguages(fileTree, manifests);
    
    // Phase 4: Framework detection
    profile.frameworks = await this.detectFrameworks(workspaceRoot, manifests, fileTree);
    
    // Phase 5: Structural analysis
    profile.hasTests = this.detectTests(fileTree);
    profile.hasCI = this.detectCI(fileTree);
    profile.hasDocumentation = this.detectDocs(fileTree);
    profile.hasApiLayer = this.detectApiLayer(fileTree, manifests);
    profile.hasDatabase = this.detectDatabase(fileTree, manifests);
    profile.hasFrontend = this.detectFrontend(fileTree, manifests);
    profile.hasBackend = this.detectBackend(fileTree, manifests);
    profile.hasInfrastructure = this.detectInfra(fileTree);
    profile.hasMobile = this.detectMobile(fileTree, manifests);
    profile.hasMLComponents = this.detectML(fileTree, manifests);
    
    // Phase 6: Complexity scoring
    profile.complexityScore = this.calculateComplexity(profile);
    profile.totalDependencies = manifests.totalDeps;
    profile.devDependencies = manifests.devDeps;
    profile.hasNativeModules = manifests.hasNative;
    profile.securitySurface = this.assessSecuritySurface(profile);
    
    // Phase 7: Existing team detection
    profile.hasAgentsMd = fileTree.some(f => f.name === 'AGENTS.md');
    profile.hasExistingTeam = fileTree.some(f => f.path.includes('agents/') && f.ext === '.md');
    profile.hasMcpServers = fileTree.some(f => f.name === '.mcp.json');
    profile.hasCustomSkills = fileTree.some(f => f.name === 'SKILL.md');
    
    // Phase 8: Line count estimation (sampled)
    profile.totalLinesOfCode = await this.estimateLinesOfCode(workspaceRoot, fileTree);
    
    return profile as ProjectProfile;
  }

  /**
   * COMPLEXITY SCORING ALGORITHM
   * 
   * Composite score from weighted indicators:
   * 
   * Score = Σ(indicator × weight) / Σ(weights)
   * 
   * Indicators (each 0-1):
   *   - Scale: log(totalFiles) / log(10000)
   *   - Language diversity: uniqueLanguages / 5 (capped at 1)
   *   - Framework count: frameworks / 4 (capped at 1)
   *   - Has monorepo: 1 if true, 0 if false
   *   - Has tests: 0.3 if true (reduces complexity), 0.7 if false
   *   - Has API + DB + Frontend: count / 3
   *   - Dependency count: log(totalDeps) / log(500)
   *   - Has infrastructure: 1 if true
   *   - Has ML: 1 if true
   *   - Security surface: low=0.2, medium=0.5, high=0.9
   * 
   * Weights:
   *   Scale: 0.15
   *   Language diversity: 0.10
   *   Framework count: 0.10
   *   Monorepo: 0.10
   *   Tests (inverse): 0.10
   *   Full-stack: 0.15
   *   Dependencies: 0.10
   *   Infrastructure: 0.05
   *   ML: 0.10
   *   Security: 0.05
   */
  private calculateComplexity(p: Partial<ProjectProfile>): number {
    const indicators = [
      { value: Math.log(p.totalFiles ?? 1) / Math.log(10000), weight: 0.15 },
      { value: Math.min((p.primaryLanguages?.length ?? 1) / 5, 1), weight: 0.10 },
      { value: Math.min((p.frameworks?.length ?? 0) / 4, 1), weight: 0.10 },
      { value: p.hasMonorepo ? 1 : 0, weight: 0.10 },
      { value: p.hasTests ? 0.3 : 0.7, weight: 0.10 },
      { value: [p.hasApiLayer, p.hasDatabase, p.hasFrontend].filter(Boolean).length / 3, weight: 0.15 },
      { value: Math.log(p.totalDependencies ?? 1) / Math.log(500), weight: 0.10 },
      { value: p.hasInfrastructure ? 1 : 0, weight: 0.05 },
      { value: p.hasMLComponents ? 1 : 0, weight: 0.10 },
      { value: { low: 0.2, medium: 0.5, high: 0.9 }[p.securitySurface ?? 'low'], weight: 0.05 },
    ];
    
    const totalWeight = indicators.reduce((s, i) => s + i.weight, 0);
    const score = indicators.reduce((s, i) => s + i.value * i.weight, 0) / totalWeight;
    
    return Math.round(score * 100);
  }
}
```

## 3.4 Team Derivation Algorithm (COMPLEX LOGIC)

```typescript
// ═══════════════════════════════════════════════════════════
// FILE: plugins/seed-team-generator/src/team-deriver.ts
// ═══════════════════════════════════════════════════════════

/**
 * TEAM DERIVATION ALGORITHM
 * 
 * Maps a ProjectProfile to a team topology using a rule-based
 * decision system with template instantiation.
 * 
 * DECISION TREE:
 * 
 * 1. ALWAYS include: Orchestrator (the main coordinating agent)
 * 
 * 2. IF complexityScore > 60:
 *    → Add: Architect (high-level design decisions)
 *    → Add: QA Reviewer (test coverage, security)
 * 
 * 3. IF hasFrontend AND hasBackend:
 *    → Add: Frontend Worker (scoped to frontend files)
 *    → Add: Backend Worker (scoped to backend files)
 *    ELSE IF hasFrontend:
 *    → Add: Frontend Worker
 *    ELSE IF hasBackend:
 *    → Add: Backend Worker
 * 
 * 4. IF hasDatabase:
 *    → Add: Database Specialist (migrations, queries, optimization)
 * 
 * 5. IF hasInfrastructure:
 *    → Add: DevOps Worker (Docker, K8s, CI/CD)
 * 
 * 6. IF hasMLComponents:
 *    → Add: ML Engineer (model training, data pipelines)
 * 
 * 7. IF hasMobile:
 *    → Add: Mobile Worker (iOS/Android specific)
 * 
 * 8. IF hasMonorepo AND workspacePackages.length > 3:
 *    → Add: Integration Worker (cross-package coordination)
 * 
 * 9. IF securitySurface === 'high':
 *    → Add: Security Auditor (vulnerability scanning, review)
 * 
 * 10. IF hasTests AND testCoverageEstimate < 0.5:
 *     → Add: Test Writer (increase coverage)
 * 
 * BUDGET ALLOCATION:
 * 
 * Total session budget is divided among agents:
 *   Orchestrator: 30% (coordinates, delegates, synthesizes)
 *   Architect: 15% (if present)
 *   Workers: (55% - architect_share) / worker_count each
 *   QA/Security: 10% (if present)
 * 
 * Example for a full-stack project (complexity 75):
 *   Orchestrator: 30%
 *   Architect: 15%
 *   Frontend Worker: 15%
 *   Backend Worker: 15%
 *   QA Reviewer: 10%
 *   Security Auditor: 10%
 *   Reserve: 5%
 */

interface TeamTopology {
  agents: AgentDefinition[];
  budgetAllocation: Map<string, number>;  // agentId → percentage
  coordinationPattern: 'hub_spoke' | 'pipeline' | 'mesh';
  maxConcurrency: number;
  escalationPath: string[];  // agentId chain for escalations
}

interface AgentDefinition {
  id: string;
  role: AgentRole;
  fileName: string;           // e.g., 'frontend-worker.md'
  systemPrompt: string;       // Generated from template + project context
  scopedPaths: string[];      // File patterns this agent can modify
  allowedTools: string[];     // Tool whitelist
  budgetPercent: number;
  maxTokensPerTurn: number;
  dependencies: string[];     // Other agent IDs this agent can delegate to
}

type AgentRole = 
  | 'orchestrator'
  | 'architect'
  | 'frontend_worker'
  | 'backend_worker'
  | 'database_specialist'
  | 'devops_worker'
  | 'ml_engineer'
  | 'mobile_worker'
  | 'integration_worker'
  | 'security_auditor'
  | 'test_writer'
  | 'qa_reviewer';

class TeamDeriver {
  
  /**
   * MAIN DERIVATION FUNCTION
   */
  derive(profile: ProjectProfile): TeamTopology {
    const agents: AgentDefinition[] = [];
    const budgetAllocation = new Map<string, number>();
    
    // ─── RULE 1: Always include Orchestrator ─────────────────
    agents.push(this.createAgent('orchestrator', profile));
    budgetAllocation.set('orchestrator', 30);
    
    // ─── RULE 2: High complexity → Architect + QA ────────────
    if (profile.complexityScore > 60) {
      agents.push(this.createAgent('architect', profile));
      budgetAllocation.set('architect', 15);
      
      agents.push(this.createAgent('qa_reviewer', profile));
      budgetAllocation.set('qa_reviewer', 10);
    }
    
    // ─── RULE 3: Full-stack detection ────────────────────────
    if (profile.hasFrontend && profile.hasBackend) {
      agents.push(this.createAgent('frontend_worker', profile));
      agents.push(this.createAgent('backend_worker', profile));
    } else if (profile.hasFrontend) {
      agents.push(this.createAgent('frontend_worker', profile));
    } else if (profile.hasBackend) {
      agents.push(this.createAgent('backend_worker', profile));
    }
    
    // ─── RULE 4: Database ────────────────────────────────────
    if (profile.hasDatabase) {
      agents.push(this.createAgent('database_specialist', profile));
    }
    
    // ─── RULE 5: Infrastructure ──────────────────────────────
    if (profile.hasInfrastructure) {
      agents.push(this.createAgent('devops_worker', profile));
    }
    
    // ─── RULE 6: ML Components ───────────────────────────────
    if (profile.hasMLComponents) {
      agents.push(this.createAgent('ml_engineer', profile));
    }
    
    // ─── RULE 7: Mobile ──────────────────────────────────────
    if (profile.hasMobile) {
      agents.push(this.createAgent('mobile_worker', profile));
    }
    
    // ─── RULE 8: Monorepo integration ────────────────────────
    if (profile.hasMonorepo && profile.workspacePackages.length > 3) {
      agents.push(this.createAgent('integration_worker', profile));
    }
    
    // ─── RULE 9: Security ────────────────────────────────────
    if (profile.securitySurface === 'high') {
      agents.push(this.createAgent('security_auditor', profile));
      budgetAllocation.set('security_auditor', 10);
    }
    
    // ─── RULE 10: Low test coverage ──────────────────────────
    if (profile.hasTests && profile.testCoverageEstimate < 0.5) {
      agents.push(this.createAgent('test_writer', profile));
    }
    
    // ─── DISTRIBUTE REMAINING BUDGET ─────────────────────────
    this.distributeBudget(agents, budgetAllocation);
    
    // ─── DETERMINE COORDINATION PATTERN ──────────────────────
    const pattern = this.selectCoordinationPattern(agents, profile);
    
    // ─── BUILD ESCALATION PATH ───────────────────────────────
    const escalationPath = this.buildEscalationPath(agents);
    
    return {
      agents,
      budgetAllocation,
      coordinationPattern: pattern,
      maxConcurrency: Math.min(agents.length - 1, 5),  // Cap at 5 concurrent
      escalationPath
    };
  }

  /**
   * AGENT TEMPLATE INSTANTIATION
   * 
   * Each role has a base template that gets customized with:
   * 1. Project-specific context (languages, frameworks, paths)
   * 2. Budget constraints
   * 3. Tool restrictions
   * 4. Coordination rules
   * 
   * Template variables:
   *   {{PROJECT_NAME}}
   *   {{PRIMARY_LANGUAGES}}
   *   {{FRAMEWORKS}}
   *   {{SCOPED_PATHS}}
   *   {{BUDGET_LIMIT}}
   *   {{COORDINATION_RULES}}
   *   {{ESCALATION_TARGET}}
   */
  private createAgent(role: AgentRole, profile: ProjectProfile): AgentDefinition {
    const template = this.getTemplate(role);
    const scopedPaths = this.deriveScopedPaths(role, profile);
    const allowedTools = this.deriveAllowedTools(role, profile);
    
    const systemPrompt = template
      .replace('{{PROJECT_NAME}}', profile.projectName)
      .replace('{{PRIMARY_LANGUAGES}}', profile.primaryLanguages.map(l => l.language).join(', '))
      .replace('{{FRAMEWORKS}}', profile.frameworks.map(f => f.name).join(', '))
      .replace('{{SCOPED_PATHS}}', scopedPaths.join(', '))
      .replace('{{COMPLEXITY_SCORE}}', String(profile.complexityScore))
      .replace('{{TOTAL_FILES}}', String(profile.totalFiles));
    
    return {
      id: role,
      role,
      fileName: `${role.replace(/_/g, '-')}.md`,
      systemPrompt,
      scopedPaths,
      allowedTools,
      budgetPercent: 0,  // Set later by distributeBudget
      maxTokensPerTurn: this.getMaxTokens(role),
      dependencies: this.getDependencies(role)
    };
  }

  /**
   * SCOPED PATH DERIVATION
   * 
   * Determines which file patterns each agent can modify.
   * This is critical for preventing cross-contamination.
   * 
   * Rules:
   *   orchestrator: ['**/*'] (can see everything, modifies nothing directly)
   *   architect: ['docs/**', 'ARCHITECTURE.md', 'DESIGN.md']
   *   frontend_worker: ['src/components/**', 'src/pages/**', 'src/styles/**', 'public/**']
   *   backend_worker: ['src/api/**', 'src/services/**', 'src/models/**', 'server/**']
   *   database_specialist: ['migrations/**', 'prisma/**', 'drizzle/**', 'sql/**']
   *   devops_worker: ['Dockerfile', 'docker-compose*', '.github/**', 'infra/**', 'k8s/**']
   *   ml_engineer: ['ml/**', 'models/**', 'training/**', 'data/**', 'notebooks/**']
   *   mobile_worker: ['ios/**', 'android/**', 'src/mobile/**', 'react-native/**']
   *   security_auditor: ['**/*'] (read-only, can flag but not modify)
   *   test_writer: ['tests/**', '__tests__/**', '*.test.*', '*.spec.*']
   *   qa_reviewer: ['**/*'] (read-only, produces review reports)
   */
  private deriveScopedPaths(role: AgentRole, profile: ProjectProfile): string[] {
    const pathMap: Record<AgentRole, string[]> = {
      orchestrator: ['**/*'],
      architect: ['docs/**', 'ARCHITECTURE.md', 'DESIGN.md', 'ADR/**'],
      frontend_worker: this.deriveFrontendPaths(profile),
      backend_worker: this.deriveBackendPaths(profile),
      database_specialist: ['migrations/**', 'prisma/**', 'drizzle/**', 'sql/**', 'db/**'],
      devops_worker: ['Dockerfile*', 'docker-compose*', '.github/**', 'infra/**', 'k8s/**', 'terraform/**'],
      ml_engineer: ['ml/**', 'models/**', 'training/**', 'data/**', 'notebooks/**', 'experiments/**'],
      mobile_worker: ['ios/**', 'android/**', 'src/mobile/**', 'react-native/**', 'flutter/**'],
      integration_worker: ['packages/**/src/index.ts', 'packages/**/package.json'],
      security_auditor: ['**/*'],  // Read-only
      test_writer: ['tests/**', '__tests__/**', '*.test.*', '*.spec.*', 'e2e/**'],
      qa_reviewer: ['**/*'],  // Read-only
    };
    
    return pathMap[role] ?? ['**/*'];
  }

  /**
   * COORDINATION PATTERN SELECTION
   * 
   * hub_spoke: Orchestrator delegates to all workers, workers report back.
   *            Best for: independent tasks, parallel work.
   *            Used when: agents have non-overlapping scoped paths.
   * 
   * pipeline: Sequential handoff (architect → worker → reviewer).
   *           Best for: dependent tasks requiring sequential refinement.
   *           Used when: complexity > 80 AND hasTests.
   * 
   * mesh: Workers can communicate directly with each other.
   *       Best for: tightly coupled systems requiring coordination.
   *       Used when: hasMonorepo AND workspacePackages > 5.
   */
  private selectCoordinationPattern(agents: AgentDefinition[], profile: ProjectProfile): 'hub_spoke' | 'pipeline' | 'mesh' {
    if (profile.hasMonorepo && profile.workspacePackages.length > 5) {
      return 'mesh';
    }
    if (profile.complexityScore > 80 && profile.hasTests) {
      return 'pipeline';
    }
    return 'hub_spoke';
  }
}
```

## 4.3 GEPA Optimization Algorithm (COMPLEX LOGIC)

```typescript
// ═══════════════════════════════════════════════════════════
// FILE: plugins/self-evolution/src/gepa-optimizer.ts
// ═══════════════════════════════════════════════════════════

/**
 * GEPA: GENETIC-PARETO PROMPT EVOLUTION
 * 
 * Adapted from ICLR 2026 Oral paper. MIT licensed.
 * 
 * Key insight: GEPA reads execution traces to understand WHY
 * things fail (not just that they failed), then proposes
 * targeted mutations. This is "reflective evolution."
 * 
 * ALGORITHM OVERVIEW:
 * 
 * 1. POPULATION INITIALIZATION
 *    - Start with the current skill/prompt as the seed organism
 *    - Generate N initial variants via random mutation
 *    - Population size: 8-12 (small, because each eval costs API calls)
 * 
 * 2. EVALUATION
 *    - Run each variant on the evaluation dataset
 *    - Collect multi-dimensional fitness scores
 *    - Capture execution traces for reflective analysis
 * 
 * 3. SELECTION (Pareto Front)
 *    - Identify non-dominated solutions across all fitness dimensions
 *    - A solution is "dominated" if another is better on ALL dimensions
 *    - The Pareto front = set of solutions not dominated by any other
 *    - Select parents from the Pareto front (diversity-preserving)
 * 
 * 4. MUTATION (Reflective)
 *    - GEPA reads failure traces from low-scoring evaluations
 *    - Proposes targeted mutations: "The agent failed because the
 *      skill didn't mention checking X. Add a step for X."
 *    - This is NOT random mutation — it's informed by failure analysis
 *    - Mutation types:
 *      a. ADD_STEP: Insert a new instruction step
 *      b. REMOVE_STEP: Delete a redundant/confusing step
 *      c. REORDER: Change the order of steps
 *      d. CLARIFY: Rewrite an ambiguous instruction
 *      e. ADD_EXAMPLE: Add a concrete example
 *      f. ADD_CONSTRAINT: Add a boundary condition
 *      g. SIMPLIFY: Reduce verbosity without losing meaning
 * 
 * 5. CROSSOVER (Optional)
 *    - Combine steps from two high-scoring parents
 *    - Only if both parents score > 0.7 on the same dimension
 *    - Crossover point: between logical sections of the skill
 * 
 * 6. CONSTRAINT FILTERING
 *    - Discard variants that violate hard constraints
 *    - (size limits, semantic drift, test failures)
 * 
 * 7. TERMINATION
 *    - Stop after max_iterations (default: 10)
 *    - OR when improvement < 2% for 3 consecutive iterations
 *    - OR when budget exhausted
 * 
 * PSEUDOCODE:
 */

interface GEPAConfig {
  populationSize: number;        // Default: 10
  maxIterations: number;         // Default: 10
  mutationRate: number;          // Default: 0.3 (30% of population mutated per gen)
  crossoverRate: number;         // Default: 0.1
  eliteCount: number;            // Default: 2 (top N carried forward unchanged)
  terminationThreshold: number;  // Default: 0.02 (2% improvement minimum)
  stagnationLimit: number;       // Default: 3 (consecutive generations without improvement)
  budgetLimitUsd: number;        // Hard stop if optimization costs exceed this
}

interface Organism {
  id: string;
  generation: number;
  text: string;                  // The skill/prompt text
  fitness: FitnessScore | null;
  traces: ExecutionTrace[];      // From evaluation runs
  parentIds: string[];           // Lineage tracking
  mutationType: string | null;   // What mutation produced this
  mutationRationale: string | null;  // WHY this mutation was proposed
}

interface FitnessScore {
  // Multi-dimensional (Pareto optimization)
  correctness: number;           // 0-1: Did it produce correct outputs?
  procedureAdherence: number;    // 0-1: Did the agent follow the procedure?
  conciseness: number;           // 0-1: Was it within token budget?
  costEfficiency: number;        // 0-1: Lower cost = higher score
  semanticPreservation: number;  // 0-1: Similarity to original intent
  composite: number;             // Weighted average (for display only)
}

class GEPAOptimizer {
  
  private config: GEPAConfig;
  private population: Organism[];
  private generation: number;
  private bestFitnessHistory: number[];
  private totalCostUsd: number;
  
  /**
   * MAIN OPTIMIZATION LOOP
   */
  async optimize(
    target: OptimizableTarget,
    evalDataset: EvalDataset,
    config: Partial<GEPAConfig> = {}
  ): Promise<EvolutionResult> {
    
    this.config = { ...DEFAULT_CONFIG, ...config };
    this.generation = 0;
    this.totalCostUsd = 0;
    this.bestFitnessHistory = [];
    
    // ─── STEP 1: INITIALIZE POPULATION ───────────────────────
    this.population = this.initializePopulation(target);
    
    // ─── STEP 2: EVALUATE INITIAL POPULATION ─────────────────
    await this.evaluatePopulation(evalDataset);
    
    // ─── STEP 3: EVOLUTIONARY LOOP ───────────────────────────
    let stagnationCount = 0;
    
    while (this.generation < this.config.maxIterations) {
      this.generation++;
      
      // Check termination conditions
      if (this.shouldTerminate(stagnationCount)) break;
      if (this.totalCostUsd >= this.config.budgetLimitUsd) break;
      
      // Select parents from Pareto front
      const paretoFront = this.computeParetoFront();
      const parents = this.selectParents(paretoFront);
      
      // Generate offspring via reflective mutation
      const offspring = await this.generateOffspring(parents, evalDataset);
      
      // Evaluate offspring
      await this.evaluatePopulation(evalDataset, offspring);
      
      // Apply constraint filters
      const valid = this.filterConstraints(offspring, target);
      
      // Merge: elites + valid offspring → new population
      const elites = this.selectElites();
      this.population = [...elites, ...valid].slice(0, this.config.populationSize);
      
      // Track improvement
      const bestFitness = Math.max(...this.population.map(o => o.fitness!.composite));
      const improvement = this.bestFitnessHistory.length > 0
        ? bestFitness - this.bestFitnessHistory[this.bestFitnessHistory.length - 1]
        : bestFitness;
      
      this.bestFitnessHistory.push(bestFitness);
      
      if (improvement < this.config.terminationThreshold) {
        stagnationCount++;
      } else {
        stagnationCount = 0;
      }
    }
    
    // ─── STEP 4: SELECT BEST VARIANT ─────────────────────────
    const best = this.population.reduce((a, b) => 
      a.fitness!.composite > b.fitness!.composite ? a : b
    );
    
    return {
      bestVariant: best,
      baseline: this.population[0],  // Original
      generations: this.generation,
      totalCostUsd: this.totalCostUsd,
      fitnessHistory: this.bestFitnessHistory,
      allVariants: this.population
    };
  }

  /**
   * REFLECTIVE MUTATION ENGINE (THE CORE INNOVATION)
   * 
   * Unlike random mutation, GEPA reads execution traces to
   * understand WHY a variant scored poorly, then proposes
   * a targeted fix.
   * 
   * ALGORITHM:
   * 
   * 1. Collect all traces where fitness.correctness < 0.6
   * 2. For each failure trace:
   *    a. Identify the step where the agent diverged
   *    b. Identify what information was missing
   *    c. Identify what constraint was violated
   * 3. Cluster failures by root cause
   * 4. For each cluster, propose a mutation:
   *    - Missing information → ADD_STEP or ADD_EXAMPLE
   *    - Ambiguous instruction → CLARIFY
   *    - Wrong order → REORDER
   *    - Redundant step → REMOVE_STEP
   *    - Missing boundary → ADD_CONSTRAINT
   * 5. Apply the mutation with highest expected impact
   * 
   * The "reflection" is done by an LLM call:
   * 
   * Prompt: "Here is a skill that scored {score}/1.0.
   *          Here are 3 execution traces where it failed:
   *          {traces}
   *          
   *          Analyze WHY the failures occurred.
   *          Propose ONE specific mutation to fix the most common failure.
   *          Respond with JSON:
   *          {mutationType, rationale, modifiedText}"
   */
  private async generateOffspring(
    parents: Organism[],
    evalDataset: EvalDataset
  ): Promise<Organism[]> {
    
    const offspring: Organism[] = [];
    const mutationCount = Math.ceil(this.config.populationSize * this.config.mutationRate);
    
    for (let i = 0; i < mutationCount; i++) {
      const parent = parents[i % parents.length];
      
      // Collect failure traces from parent's evaluations
      const failureTraces = parent.traces.filter(t => t.fitness.correctness < 0.6);
      
      if (failureTraces.length === 0) {
        // No failures → apply random exploration mutation
        offspring.push(this.randomMutation(parent));
        continue;
      }
      
      // ─── REFLECTIVE ANALYSIS ─────────────────────────────────
      const reflectionPrompt = this.buildReflectionPrompt(parent, failureTraces);
      const reflection = await this.callModel('strong', reflectionPrompt);
      const parsed = JSON.parse(reflection);
      
      // Create offspring with the proposed mutation
      const child: Organism = {
        id: `gen${this.generation}_mut${i}`,
        generation: this.generation,
        text: parsed.modifiedText,
        fitness: null,
        traces: [],
        parentIds: [parent.id],
        mutationType: parsed.mutationType,
        mutationRationale: parsed.rationale
      };
      
      offspring.push(child);
    }
    
    // ─── CROSSOVER (optional) ──────────────────────────────────
    if (Math.random() < this.config.crossoverRate && parents.length >= 2) {
      const [p1, p2] = this.selectCrossoverParents(parents);
      const child = this.crossover(p1, p2);
      offspring.push(child);
    }
    
    return offspring;
  }

  /**
   * PARETO FRONT COMPUTATION
   * 
   * Multi-objective optimization: a solution is "non-dominated"
   * if no other solution is better on ALL dimensions simultaneously.
   * 
   * ALGORITHM (fast non-dominated sort):
   * 
   * For each solution p in population:
   *   domination_count[p] = 0
   *   dominated_set[p] = []
   *   
   *   For each other solution q:
   *     IF p dominates q (p better on all dims):
   *       dominated_set[p].append(q)
   *     ELSE IF q dominates p:
   *       domination_count[p] += 1
   *   
   *   IF domination_count[p] == 0:
   *     p is on the Pareto front (rank 1)
   * 
   * "p dominates q" means:
   *   p.correctness >= q.correctness AND
   *   p.procedureAdherence >= q.procedureAdherence AND
   *   p.conciseness >= q.conciseness AND
   *   p.costEfficiency >= q.costEfficiency AND
   *   p.semanticPreservation >= q.semanticPreservation AND
   *   (at least one is strictly greater)
   */
  private computeParetoFront(): Organism[] {
    const scored = this.population.filter(o => o.fitness !== null);
    const front: Organism[] = [];
    
    for (const p of scored) {
      let dominated = false;
      for (const q of scored) {
        if (p.id === q.id) continue;
        if (this.dominates(q.fitness!, p.fitness!)) {
          dominated = true;
          break;
        }
      }
      if (!dominated) {
        front.push(p);
      }
    }
    
    return front.length > 0 ? front : scored.slice(0, 3);  // Fallback
  }

  private dominates(a: FitnessScore, b: FitnessScore): boolean {
    const dims: (keyof FitnessScore)[] = [
      'correctness', 'procedureAdherence', 'conciseness',
      'costEfficiency', 'semanticPreservation'
    ];
    
    let allGreaterOrEqual = true;
    let anyStrictlyGreater = false;
    
    for (const dim of dims) {
      if (a[dim] < b[dim]) { allGreaterOrEqual = false; break; }
      if (a[dim] > b[dim]) { anyStrictlyGreater = true; }
    }
    
    return allGreaterOrEqual && anyStrictlyGreater;
  }
}
```

## 4.4 Fitness Function Composition (COMPLEX LOGIC)

```typescript
// ═══════════════════════════════════════════════════════════
// FILE: plugins/self-evolution/src/fitness.ts
// ═══════════════════════════════════════════════════════════

/**
 * MULTI-DIMENSIONAL FITNESS EVALUATION
 * 
 * Each evolved variant is scored on 5 dimensions.
 * The composite score is a weighted average, but the Pareto
 * optimizer uses all dimensions independently.
 * 
 * DIMENSION WEIGHTS (for composite display only):
 *   correctness: 0.35
 *   procedureAdherence: 0.20
 *   conciseness: 0.15
 *   costEfficiency: 0.15
 *   semanticPreservation: 0.15
 */

class FitnessEvaluator {
  
  /**
   * CORRECTNESS (0-1)
   * 
   * LLM-as-Judge with skill-specific rubrics.
   * 
   * Process:
   * 1. Run the variant on N evaluation tasks (via ZCode workflow engine)
   * 2. For each task, capture the agent's output
   * 3. Send (task, expected_behavior, actual_output) to a judge model
   * 4. Judge scores on rubric:
   *    - Did the output satisfy the expected behavior? (0-1)
   *    - Was the output factually correct? (0-1)
   *    - Were there any harmful/incorrect suggestions? (0-1, inverted)
   * 5. Average across all tasks
   * 
   * Judge prompt template:
   * "You are evaluating an AI agent's output.
   *  
   *  Task: {task}
   *  Expected behavior: {expected_behavior}
   *  Actual output: {actual_output}
   *  
   *  Score the output on these criteria (0.0 to 1.0):
   *  1. Task completion: Did it accomplish what was asked?
   *  2. Correctness: Is the information accurate?
   *  3. Safety: Are there any harmful suggestions?
   *  
   *  Respond with JSON: {completion, correctness, safety, overall}"
   */
  async evaluateCorrectness(
    variant: Organism,
    evalTasks: EvalTask[]
  ): Promise<number> {
    const scores: number[] = [];
    
    for (const task of evalTasks) {
      // Run the variant on this task
      const output = await this.runVariantOnTask(variant, task);
      
      // Judge the output
      const judgment = await this.judgeOutput(task, output);
      scores.push(judgment.overall);
    }
    
    return scores.reduce((s, v) => s + v, 0) / scores.length;
  }

  /**
   * PROCEDURE ADHERENCE (0-1)
   * 
   * Measures whether the agent followed the skill's prescribed steps.
   * 
   * Process:
   * 1. Parse the skill text to extract ordered steps
   * 2. Parse the execution trace to identify which steps were taken
   * 3. Calculate: steps_taken / total_steps
   * 4. Penalize out-of-order execution: -0.1 per inversion
   * 5. Penalize skipped critical steps: -0.2 per skip
   * 
   * Step extraction uses regex on numbered lists, headers, and
   * imperative sentences in the skill text.
   */
  evaluateProcedureAdherence(
    variant: Organism,
    traces: ExecutionTrace[]
  ): number {
    const steps = this.extractSteps(variant.text);
    let totalAdherence = 0;
    
    for (const trace of traces) {
      const takenSteps = this.identifyTakenSteps(trace, steps);
      const coverage = takenSteps.length / steps.length;
      
      // Penalize inversions
      const inversions = this.countInversions(takenSteps, steps);
      const inversionPenalty = inversions * 0.1;
      
      // Penalize skipped critical steps (marked with "MUST" or "ALWAYS")
      const criticalSkips = this.countCriticalSkips(takenSteps, steps);
      const criticalPenalty = criticalSkips * 0.2;
      
      const adherence = Math.max(0, coverage - inversionPenalty - criticalPenalty);
      totalAdherence += adherence;
    }
    
    return totalAdherence / traces.length;
  }

  /**
   * CONCISENESS (0-1)
   * 
   * Penalizes verbosity. Uses a length penalty curve:
   * 
   * score = 1.0 if tokens <= target_tokens
   * score = 1.0 - 0.5 * ((tokens - target) / target) if tokens > target
   * score = 0.0 if tokens > 2 * target
   * 
   * Target tokens per skill type:
   *   Simple skill (1-3 steps): 500 tokens
   *   Medium skill (4-8 steps): 1200 tokens
   *   Complex skill (9+ steps): 2500 tokens
   * 
   * Hard limit: 15KB (from Hermes constraint)
   */
  evaluateConciseness(variant: Organism): number {
    const tokens = this.countTokens(variant.text);
    const target = this.getTargetTokens(variant.text);
    const hardLimit = 3750;  // ~15KB at 4 chars/token
    
    if (tokens > hardLimit) return 0;
    if (tokens <= target) return 1.0;
    
    const overshoot = (tokens - target) / target;
    return Math.max(0, 1.0 - 0.5 * overshoot);
  }

  /**
   * COST EFFICIENCY (0-1)
   * 
   * Measures how much the variant costs to execute vs baseline.
   * 
   * score = baseline_cost / variant_cost (capped at 1.0)
   * 
   * If variant is cheaper than baseline → score = 1.0
   * If variant is 2x more expensive → score = 0.5
   * If variant is 4x more expensive → score = 0.25
   */
  evaluateCostEfficiency(
    variant: Organism,
    baseline: Organism,
    evalTasks: EvalTask[]
  ): number {
    const variantCost = this.estimateExecutionCost(variant, evalTasks);
    const baselineCost = this.estimateExecutionCost(baseline, evalTasks);
    
    if (variantCost <= baselineCost) return 1.0;
    return Math.max(0.1, baselineCost / variantCost);
  }

  /**
   * SEMANTIC PRESERVATION (0-1)
   * 
   * Ensures the evolved variant hasn't drifted from its original purpose.
   * 
   * Process:
   * 1. Generate embeddings for original and variant text
   * 2. Calculate cosine similarity
   * 3. Score = similarity (0-1)
   * 
   * Threshold: If similarity < 0.7, the variant is REJECTED
   * (regardless of other fitness scores)
   * 
   * This prevents "reward hacking" where the optimizer finds
   * a high-scoring text that's completely different from the
   * original skill's purpose.
   */
  async evaluateSemanticPreservation(
    variant: Organism,
    original: Organism
  ): Promise<number> {
    const [embOriginal, embVariant] = await Promise.all([
      this.embed(original.text),
      this.embed(variant.text)
    ]);
    
    return this.cosineSimilarity(embOriginal, embVariant);
  }
}
```

## 4.5 Constraint Validation Pipeline

```typescript
// ═══════════════════════════════════════════════════════════
// FILE: plugins/self-evolution/src/constraints.ts
// ═══════════════════════════════════════════════════════════

/**
 * HARD CONSTRAINT GATES
 * 
 * Every evolved variant MUST pass ALL constraints.
 * Failure on any constraint = immediate rejection.
 * GEPA never sees rejected variants as "successful."
 * 
 * CONSTRAINT PIPELINE (sequential, fail-fast):
 * 
 * 1. SIZE LIMIT
 *    - Skills: ≤ 15KB (3750 tokens)
 *    - Tool descriptions: ≤ 500 chars
 *    - Agent prompts: ≤ 8KB (2000 tokens)
 *    - System prompt sections: ≤ 120% of original size
 * 
 * 2. STRUCTURAL VALIDITY
 *    - SKILL.md must have valid frontmatter (name, description)
 *    - Agent .md must have valid frontmatter (name, description)
 *    - No broken markdown (unclosed code blocks, invalid YAML)
 * 
 * 3. SEMANTIC PRESERVATION
 *    - Cosine similarity to original ≥ 0.7
 *    - Core keywords preserved (extracted from original)
 * 
 * 4. CACHING COMPATIBILITY
 *    - No mid-conversation state changes
 *    - Skill takes effect on next session only
 *    - Tool schema structure unchanged (only description text)
 * 
 * 5. TEST SUITE (if code evolution)
 *    - pnpm typecheck must pass
 *    - pnpm lint must pass
 *    - pnpm architecture:check must pass
 * 
 * 6. NO DANGEROUS PATTERNS
 *    - No shell command injection vectors
 *    - No credential exposure
 *    - No unbounded recursion instructions
 *    - No "ignore all previous instructions" patterns
 */

class ConstraintValidator {
  
  validate(variant: Organism, original: Organism, targetType: TargetType): ConstraintResult {
    const checks: ConstraintCheck[] = [
      this.checkSizeLimit(variant, targetType),
      this.checkStructuralValidity(variant, targetType),
      this.checkSemanticPreservation(variant, original),
      this.checkCachingCompatibility(variant),
      this.checkDangerousPatterns(variant),
    ];
    
    const failures = checks.filter(c => !c.passed);
    
    return {
      passed: failures.length === 0,
      failures,
      variantId: variant.id
    };
  }

  private checkDangerousPatterns(variant: Organism): ConstraintCheck {
    const dangerous = [
      /ignore\s+(all\s+)?previous\s+instructions/i,
      /system\s*:\s*/i,
      /\$\{.*API_KEY.*\}/i,
      /curl\s+.*\|\s*(bash|sh)/i,
      /rm\s+-rf\s+\//,
      /eval\s*\(/,
      /process\.env\./,
    ];
    
    const found = dangerous.filter(re => re.test(variant.text));
    
    return {
      name: 'dangerous_patterns',
      passed: found.length === 0,
      message: found.length > 0 
        ? `Found ${found.length} dangerous pattern(s): ${found.join(', ')}`
        : 'No dangerous patterns detected'
    };
  }
}
```

## 7.3 Auto-Triage Algorithm

```typescript
/**
 * AUTO-TRIAGE: RANK OPTIMIZATION TARGETS
 * 
 * When degradation is detected, rank all evolvable targets
 * by expected impact.
 * 
 * RANKING FORMULA:
 * 
 * priority(target) = impact_score × frequency × (1 - last_evolved_recency)
 * 
 * Where:
 *   impact_score = 1.0 - current_success_rate
 *     (lower success rate = higher impact potential)
 *   
 *   frequency = usage_count_last_30_days / total_usage_last_30_days
 *     (more frequently used = higher priority)
 *   
 *   last_evolved_recency = days_since_last_evolution / 90
 *     (recently evolved = lower priority, avoid thrashing)
 * 
 * THRESHOLDS:
 *   - Skill success rate < 70% → flag for evolution
 *   - Tool misselection rate > 15% → flag for description evolution
 *   - Benchmark score drop > 3% → flag for investigation
 *   - User correction rate > 20% → flag for prompt evolution
 * 
 * OUTPUT: Ranked list of targets with:
 *   - target name
 *   - current metrics
 *   - expected improvement
 *   - estimated optimization cost
 *   - recommended action
 */
```

# PART VIII: MULTI-AGENT ORCHESTRATION GOVERNANCE

## 8.1 Purpose

Govern how the orchestrator agent creates, manages, and terminates multi-agent workflows with full cost awareness and team coordination.

## 8.2 Orchestration Protocol

```typescript
/**
 * ORCHESTRATION GOVERNANCE RULES
 * 
 * These rules are injected into the orchestrator's system prompt
 * via the SessionStart hook.
 * 
 * RULE 1: COST-AWARE PLANNING
 * Before generating any multi-step workflow:
 *   a. Call get_budget_status() to check remaining budget
 *   b. Estimate cost of each step using the Token Estimator
 *   c. If total estimated cost > 60% of remaining budget:
 *      → Simplify the plan (fewer steps, smaller context)
 *      → OR request budget increase from user
 *   d. Include cost estimates in the workflow plan output
 * 
 * RULE 2: TEAM-AWARE DELEGATION
 * Before spawning a sub-agent:
 *   a. Check if an existing team member matches the task
 *   b. Route to the most specific matching agent
 *   c. Include the agent's scoped paths in the delegation
 *   d. Set the agent's budget allocation for this task
 *   e. Never spawn a new agent if an existing one can do the job
 * 
 * RULE 3: CONCURRENCY GOVERNANCE
 * Maximum concurrent sub-agents:
 *   - Default: 3 (configurable)
 *   - Never exceed budget / (min_cost_per_agent)
 *   - If a workflow has > 5 parallel branches:
 *     → Serialize into batches of 3
 *     → Report progress between batches
 * 
 * RULE 4: ESCALATION PROTOCOL
 * Escalate to human when:
 *   - Budget remaining < 10%
 *   - A sub-agent fails 3 consecutive times
 *   - A task requires modifying files outside all agents' scopes
 *   - A security-sensitive operation is requested
 *   - The workflow has been running > 30 minutes
 * 
 * RULE 5: SYNTHESIS REQUIREMENT
 * After all sub-agents complete:
 *   - Orchestrator MUST synthesize results
 *   - Orchestrator MUST verify consistency between agents
 *   - Orchestrator MUST report total cost vs estimate
 *   - Orchestrator MUST flag any conflicts between agent outputs
 */
```

## 10.2 Invariant Safety Rules

```
INVARIANT 1: HUMAN GATE ON DEPLOYMENT
  No evolved artifact is ever deployed without human approval.
  All changes go through PR. No auto-merge. No exceptions.

INVARIANT 2: BUDGET HARD LIMIT
  The budget governor's DENY decision cannot be overridden
  by the agent. Only the user can override via explicit
  environment variable. The agent cannot set this variable.

INVARIANT 3: SEMANTIC ANCHOR
  Every evolved variant must maintain cosine similarity ≥ 0.7
  with its original. This cannot be relaxed by configuration.

INVARIANT 4: NO SELF-MODIFICATION OF SAFETY CODE
  The evolution engine cannot evolve:
  - Its own fitness functions
  - Its own constraint validators
  - The budget governor's decision matrix
  - The benchmark gate thresholds
  These are FROZEN. Only human developers can modify them.

INVARIANT 5: TRACE IMMUTABILITY
  Execution traces are append-only. No agent or process can
  delete or modify trace entries. This prevents the system
  from hiding its own failures.

INVARIANT 6: KILL SWITCH
  Setting ZCODE_EVOLUTION_DISABLED=true immediately stops
  all evolution, monitoring, and auto-triage. The system
  reverts to static operation. This cannot be unset by
  the agent.
```

```typescript
// plugins/budget-governor/src/estimator.ts

/**
 * ESTIMATION TIER SELECTION (Decision Tree):
 * 
 * Tier 1: Character Heuristic (~10ms, ±30% accuracy)
 *   - chars / 4 ≈ tokens (English)
 *   - chars / 2 ≈ tokens (CJK)
 *   - Used for: high-frequency operations
 * 
 * Tier 2: Tiktoken Exact (~30ms, ±5% accuracy)
 *   - Actual tokenizer count
 *   - Used for: workflow validation
 * 
 * Tier 3: Historical Average (~5ms, ±15% accuracy)
 *   - Mean of last N similar operations
 *   - Used for: recurring operations
 * 
 * Tier 4: LLM Prediction (~500ms, ±10% accuracy)
 *   - Cheap model predicts output length
 *   - Used for: novel, high-stakes operations
 */

interface CostEstimate {
  operationId: string;
  operationType: 'workflow_step' | 'subagent_spawn' | 'tool_call';
  modelId: string;
  estimatedInputTokens: number;
  estimatedOutputTokens: number;
  estimatedCostUsd: number;
  confidenceLevel: 'high' | 'medium' | 'low';
  estimationMethod: 'char_heuristic' | 'tiktoken' | 'historical_average' | 'llm_prediction';
}
```

### 1.2.2 PreToolUse Hook (budget-checker.mjs)

Intercepts `Agent`, `Task`, `Workflow`, `delegate_task` tool calls.

**Decision Matrix:**

| Estimated Cost / Remaining Budget | Decision |
|---|---|
| < 10% | ALLOW |
| 10% - 30% | ALLOW + warn |
| 30% - 60% | SIMPLIFY (suggest alternatives) |
| 60% - 90% | ESCALATE to human |
| > 90% | DENY |
| > 100% | DENY (hard block) |

### 1.2.3 Budget Ledger (MCP Server)

SQLite database at `~/.zcode/budget-ledger.db`:
- Sessions table (per-session budgets)
- Agents table (per-agent allocations within sessions)
- Ledger_entries table (actual usage records)
- Project_budgets table (monthly caps)

# PHASE 5: GEPA SELF-EVOLUTION ENGINE (Weeks 9-12)

## 5.1 Why Fifth

- **The crown jewel** — requires all prior phases
- Highest complexity, highest long-term value
- Adapted from `NousResearch/hermes-agent-self-evolution` (MIT)
- 4 weeks because of complexity

## 5.2 GEPA Algorithm Overview

```
┌─────────────────────────────────────────────────────────────┐
│  1. SELECT TARGET (skill/prompt/description)                │
│  2. BUILD EVALUATION DATASET (from Phase 3 traces)          │
│  3. WRAP AS DSPy MODULE                                    │
│  4. INITIALIZE POPULATION (8-12 variants)                   │
│  5. EVALUATE (5-dimensional fitness)                        │
│  6. COMPUTE PARETO FRONT (non-dominated solutions)          │
│  7. SELECT PARENTS from Pareto front                        │
│  8. REFLECTIVE MUTATION (read failure traces)               │
│  9. CROSSOVER (optional)                                    │
│ 10. CONSTRAINT FILTER (size, semantics, tests)              │
│ 11. NEW GENERATION → back to step 5                         │
│ 12. STOP after max_iterations or stagnation                 │
│ 13. DEPLOY best variant via PR                              │
└─────────────────────────────────────────────────────────────┘
```

## 5.3 Key Innovation: Reflective Mutation

Unlike random mutation, GEPA reads execution traces to understand **why** failures happen:

```
Failure trace: "Agent skipped step 3 (verify tests pass)"
    │
    ▼
LLM analysis: "The skill didn't emphasize the importance of test verification"
    │
    ▼
Targeted mutation: ADD_CONSTRAINT "MUST run tests before committing"
```

## 5.4 Fitness Functions (5 Dimensions)

| Dimension | What It Measures | Scoring Method |
|---|---|---|
| **Correctness** | Did output satisfy task? | LLM-as-judge with rubric |
| **Procedure Adherence** | Did agent follow skill steps? | Step coverage analysis |
| **Conciseness** | Is skill within token budget? | Length penalty curve |
| **Cost Efficiency** | Is variant cheaper than baseline? | Cost ratio |
| **Semantic Preservation** | Did meaning stay similar? | Cosine similarity ≥ 0.7 |

## 5.5 Pareto Selection

A variant is "non-dominated" if no other variant is better on ALL dimensions. This preserves diversity and prevents optimization collapse.

## 5.6 Constraint Gates (Hard)

Every variant MUST pass:
1. Size limit: Skills ≤ 15KB, tools ≤ 500 chars
2. Semantic preservation: Cosine similarity ≥ 0.7
3. Dangerous pattern filter: No prompt injection vectors
4. Test suite: `pnpm typecheck && pnpm lint` must pass
5. Benchmark gate: No >2% regression on ZCODE-CORE

# PHASE 6: CONTINUOUS IMPROVEMENT LOOP (Weeks 13-14)

## 6.1 Why Sixth

- **Automates the evolution trigger**
- Builds on Phase 3 traces + Phase 5 evolution
- Moderate complexity, high operational value

## 6.2 Components

### Performance Monitor
- Aggregates trace data daily
- Computes per-skill success rates
- Detects threshold breaches:
  - Skill success rate < 70% → flag
  - Tool misselection > 15% → flag
  - User correction rate > 20% → flag

### Auto-Triage
```typescript
priority(target) = impact_score × frequency × (1 - recency_penalty)

Where:
  impact_score = 1.0 - current_success_rate
  frequency = usage_count / total_usage
  recency_penalty = days_since_last_evolution / 90
```

### Scheduled Jobs
- **Daily:** Aggregate traces, check thresholds (~$0.50)
- **Weekly:** Run benchmark suites (~$20)
- **Monthly:** Full benchmark + dataset refresh (~$50)
- **On-demand:** Trigger evolution when threshold breached

## 6.3 State Machine

```
IDLE ──(cron/trigger)──► MONITOR ──(all OK)──► IDLE
                         │
                         ├──(degraded)──► TRIAGE ──► OPTIMIZE ──► VALIDATE ──► PR ──► REPORT ──► IDLE
```

# ADDENDUM: THE FORESIGHT ENGINE

**Dogfood Start:** Week 1 (runs in parallel with Phase 1)

## THE PROBLEM WITH REACTIVE SYSTEMS

Everything in the current blueprint follows this pattern:

```
EVENT HAPPENS → HOOK FIRES → RESPONSE TRIGGERED
```

This means:
- Budget overruns are caught **at the moment of overspend** (too late to plan around)
- Team mismatches are discovered **when a task fails** (after the damage)
- Dependency problems surface **when the build breaks** (after months of accumulation)
- Roadmap divergence is noticed **when the deadline is missed** (after the opportunity)

**What's needed is a system that operates on this pattern:**

```
CONTINUOUS MODEL → PATTERN DETECTED → WARNING ISSUED → INTERVENTION PLANNED
                                                              ↑
                                                    (before the event happens)
```

This is not another hook. This is a **parallel cognitive system** — a digital twin of the project that runs alongside the event-driven system, always watching, always modeling, always predicting.

## THE ANALYSIS ENGINE

This runs on a **periodic cycle** (not event-driven). Default: every 15 minutes during active sessions, daily during idle.

### 1. Divergence Detector

**Purpose:** Find gaps between what was planned/expected and what is actually happening.

```typescript
interface DivergenceCheck {
  id: string;
  name: string;
  expected: any;
  actual: any;
  divergenceScore: number;      // 0-1, higher = more divergent
  trend: 'converging' | 'stable' | 'diverging';
  timeToCritical?: number;      // when divergence becomes critical
}

/**
 * DIVERGENCE CHECKS:
 * 
 * 1. Budget Divergence
 *    Expected: Linear spend across session duration
 *    Actual: Current spend rate
 *    Critical when: Projected spend > budget × 1.2
 * 
 * 2. Roadmap Divergence
 *    Expected: Milestone X complete by date Y
 *    Actual: Progress rate suggests completion by date Z
 *    Critical when: Z > Y × 1.5
 * 
 * 3. Team Composition Divergence
 *    Expected: Team matches project needs (from scanner)
 *    Actual: Current team vs current project state
 *    Critical when: Match score < 0.6
 * 
 * 4. Skill Effectiveness Divergence
 *    Expected: Skill success rate ≥ 80%
 *    Actual: Rolling 30-day success rate
 *    Critical when: Rate < 60% for 7 consecutive days
 * 
 * 5. Architecture Divergence
 *    Expected: architecture-policy.yaml constraints hold
 *    Actual: Current codebase metrics
 *    Critical when: Any constraint violated
 * 
 * 6. Cost Model Divergence
 *    Expected: Estimator accuracy within ±20%
 *    Actual: Variance between estimates and actuals
 *    Critical when: Variance > 40% for 5 consecutive operations
 */

class DivergenceDetector {
  
  checkBudgetDivergence(graph: KnowledgeGraph): DivergenceCheck[] {
    const warnings: DivergenceCheck[] = [];
    
    for (const session of graph.getActiveSessions()) {
      const elapsed = Date.now() - session.startTime;
      const expectedDuration = session.expectedDuration ?? 3600000; // 1hr default
      const expectedSpend = session.budget * (elapsed / expectedDuration);
      const actualSpend = session.spent;
      
      const divergence = Math.abs(actualSpend - expectedSpend) / session.budget;
      
      if (divergence > 0.3) {
        // Project forward
        const rate = actualSpend / elapsed;
        const timeToExhaustion = (session.budget - actualSpend) / rate;
        
        warnings.push({
          id: `budget-${session.id}`,
          name: 'Budget Trajectory Divergence',
          expected: `Linear spend, $${expectedSpend.toFixed(2)} by now`,
          actual: `$${actualSpend.toFixed(2)} spent`,
          divergenceScore: Math.min(divergence, 1.0),
          trend: actualSpend > expectedSpend ? 'diverging' : 'converging',
          timeToCritical: timeToExhaustion
        });
      }
    }
    
    return warnings;
  }

  checkTeamCompositionDivergence(graph: KnowledgeGraph): DivergenceCheck[] {
    const warnings: DivergenceCheck[] = [];
    
    // Re-scan project to get current needs
    const currentProfile = graph.getProjectProfile();
    const currentTeam = graph.getTeamComposition();
    
    // What team SHOULD exist for this project
    const idealTeam = this.deriveIdealTeam(currentProfile);
    
    // Compare
    const missing = idealTeam.filter(r => !currentTeam.includes(r));
    const excess = currentTeam.filter(r => !idealTeam.includes(r));
    
    const matchScore = 1 - (missing.length + excess.length) / 
                        Math.max(idealTeam.length, currentTeam.length);
    
    if (matchScore < 0.7) {
      warnings.push({
        id: 'team-composition',
        name: 'Team Composition Drift',
        expected: `Team with: ${idealTeam.join(', ')}`,
        actual: `Current team: ${currentTeam.join(', ')}`,
        divergenceScore: 1 - matchScore,
        trend: 'diverging',
        timeToCritical: undefined  // Not time-critical, but affects quality
      });
    }
    
    return warnings;
  }

  checkRoadmapDivergence(graph: KnowledgeGraph): DivergenceCheck[] {
    const warnings: DivergenceCheck[] = [];
    
    for (const item of graph.getRoadmapItems()) {
      if (item.status !== 'in_progress') continue;
      
      const elapsed = Date.now() - item.startDate;
      const progress = item.actualEffort / item.estimatedEffort;
      const expectedProgress = elapsed / (item.deadline - item.startDate);
      
      const divergence = expectedProgress - progress;
      
      if (divergence > 0.2) {
        // Project completion date
        const rate = item.actualEffort / elapsed;
        const remaining = item.estimatedEffort - item.actualEffort;
        const projectedCompletion = Date.now() + (remaining / rate);
        
        const feasibilityScore = item.deadline > projectedCompletion ? 
          (item.deadline - projectedCompletion) / (item.deadline - Date.now()) : 0;
        
        warnings.push({
          id: `roadmap-${item.id}`,
          name: `Roadmap Item "${item.title}" At Risk`,
          expected: `${(expectedProgress * 100).toFixed(0)}% complete by now`,
          actual: `${(progress * 100).toFixed(0)}% complete`,
          divergenceScore: Math.min(divergence * 2, 1.0),
          trend: 'diverging',
          timeToCritical: item.deadline - Date.now()
        });
      }
    }
    
    return warnings;
  }
}
```

### 2. Trajectory Projector

**Purpose:** Extrapolate current rates to predict future states.

```typescript
/**
 * TRAJECTORY PROJECTION ALGORITHM
 * 
 * For any metric M with time series [m1, m2, ..., mn]:
 * 
 * 1. Calculate rate of change: r = (mn - m1) / (tn - t1)
 * 2. Calculate acceleration: a = rate of change of rate
 * 3. Project forward:
 *    - Linear: M(t) = mn + r × (t - tn)
 *    - Quadratic: M(t) = mn + r × dt + 0.5 × a × dt²
 *    - Exponential: M(t) = mn × e^(r × dt) (if growth is multiplicative)
 * 4. Find ceiling intersection:
 *    - When does M(t) hit the budget/limit?
 *    - When does M(t) hit the warning threshold?
 * 
 * METRICS PROJECTED:
 *   - Token usage per day → monthly budget exhaustion date
 *   - Cost per session → monthly cost projection
 *   - File line count per module → when module exceeds policy limit
 *   - Dependency count → when dependency surface becomes unmanageable
 *   - Agent workload → when agent hits capacity
 *   - Skill failure rate → when skill needs evolution
 */

interface TrajectoryProjection {
  metric: string;
  currentValue: number;
  rateOfChange: number;         // units per day
  acceleration: number;         // change in rate per day
  projectedValues: { date: number; value: number }[];
  ceilingIntersection?: number;  // timestamp when ceiling hit
  warningIntersection?: number;  // timestamp when warning threshold hit
  model: 'linear' | 'quadratic' | 'exponential';
  confidence: number;            // based on data points and fit quality
}

class TrajectoryProjector {
  
  project(
    timeSeries: { timestamp: number; value: number }[],
    ceiling: number,
    warningThreshold: number
  ): TrajectoryProjection {
    
    if (timeSeries.length < 3) {
      return { metric: 'unknown', currentValue: 0, rateOfChange: 0, 
               acceleration: 0, projectedValues: [], model: 'linear', confidence: 0 };
    }
    
    // Fit models and pick best
    const linearFit = this.fitLinear(timeSeries);
    const quadraticFit = this.fitQuadratic(timeSeries);
    const exponentialFit = this.fitExponential(timeSeries);
    
    const bestFit = this.selectBestFit([linearFit, quadraticFit, exponentialFit]);
    
    // Project forward 30 days
    const now = Date.now();
    const projections = [];
    for (let d = 1; d <= 30; d++) {
      const t = now + d * 86400000;
      projections.push({ date: t, value: bestFit.predict(t) });
    }
    
    // Find intersections
    const ceilingIntersection = this.findIntersection(projections, ceiling);
    const warningIntersection = this.findIntersection(projections, warningThreshold);
    
    return {
      metric: timeSeries[0]?.metric ?? 'unknown',
      currentValue: timeSeries[timeSeries.length - 1].value,
      rateOfChange: bestFit.rate,
      acceleration: bestFit.acceleration ?? 0,
      projectedValues: projections,
      ceilingIntersection,
      warningIntersection,
      model: bestFit.type,
      confidence: bestFit.r2
    };
  }
}
```

### 3. Topology Analyzer (Resource Sink Shape)

**Purpose:** When a problem is detected, understand its **shape** — not just that it exists, but its topology, growth pattern, blast radius, and intervention points.

```typescript
/**
 * RESOURCE SINK TOPOLOGY
 * 
 * A "resource sink" is any pattern that consumes disproportionate
 * resources relative to its value output.
 * 
 * THE SHAPE OF A SINK:
 * 
 * 1. INPUT TOPOLOGY: What feeds into it?
 *    - Which files/modules contribute to this sink?
 *    - Which agents spend time on it?
 *    - Which workflows route through it?
 *    
 * 2. OUTPUT TOPOLOGY: What depends on it?
 *    - What breaks if this sink grows unchecked?
 *    - What downstream systems are affected?
 *    - What users/features depend on this?
 *    
 * 3. GROWTH PATTERN: How is it growing?
 *    - Linear: Steady accumulation (manageable)
 *    - Exponential: Compounding growth (dangerous)
 *    - Bounded: Approaching a natural limit (watch)
 *    - Episodic: Spikes during certain activities (plan around)
 *    
 * 4. BLAST RADIUS: What breaks if it becomes critical?
 *    - Direct: What immediately fails
 *    - Indirect: What fails as a consequence
 *    - Cascading: What fails as a consequence of the indirect failures
 *    
 * 5. INTERVENTION POINTS: Where can we act?
 *    - Upstream: Prevent input to the sink
 *    - At the sink: Reduce the sink's consumption
 *    - Downstream: Mitigate the sink's effects
 *    - Structural: Redesign to eliminate the sink
 *    
 * 6. TIME-TO-IMPACT: When does this become a real problem?
 *    - Immediate: Already causing issues
 *    - Days: Will cause issues within the week
 *    - Weeks: Will cause issues within the month
 *    - Months: Long-term accumulation
 */

interface ResourceSinkAnalysis {
  sinkId: string;
  sinkType: 'dependency_node' | 'budget_drain' | 'workload_concentration' | 
            'technical_debt' | 'scope_creep' | 'skill_decay' | 'team_mismatch';
  
  // What it is
  description: string;
  currentValue: number;
  threshold: number;
  
  // Shape
  inputTopology: string[];       // What feeds into it
  outputTopology: string[];      // What depends on it
  growthPattern: 'linear' | 'exponential' | 'bounded' | 'episodic';
  growthRate: number;            // units per week
  
  // Impact
  blastRadius: {
    direct: string[];            // Immediately affected
    indirect: string[];          // Second-order effects
    cascading: string[];         // Third-order effects
  };
  
  // Intervention
  interventionPoints: Intervention[];
  timeToImpact: number;          // milliseconds until critical
  timeToCritical: number;        // milliseconds until catastrophic
  
  // Severity
  severity: 'informational' | 'warning' | 'critical';
  confidence: number;            // 0-1
}

interface Intervention {
  action: string;
  target: string;                // What to change
  cost: number;                  // Estimated effort/cost
  effectiveness: number;         // 0-1, how much it reduces the sink
  urgency: 'immediate' | 'this_week' | 'this_month' | 'planned';
  sideEffects?: string[];
}

class TopologyAnalyzer {
  
  /**
   * ANALYZE A DETECTED SINK
   * 
   * Given a detected anomaly or divergence, trace its topology
   * through the knowledge graph.
   */
  analyzeSink(
    graph: KnowledgeGraph,
    sinkNodeId: string,
    sinkType: string
  ): ResourceSinkAnalysis {
    
    // 1. Trace inputs (what feeds into this node)
    const inputs = graph.getIncomingEdges(sinkNodeId, { depth: 3 });
    
    // 2. Trace outputs (what depends on this node)
    const outputs = graph.getOutgoingEdges(sinkNodeId, { depth: 3 });
    
    // 3. Determine growth pattern from time series
    const history = graph.getNodeHistory(sinkNodeId);
    const growthPattern = this.classifyGrowth(history);
    const growthRate = this.calculateGrowthRate(history);
    
    // 4. Calculate blast radius
    const blastRadius = this.calculateBlastRadius(graph, sinkNodeId, outputs);
    
    // 5. Identify intervention points
    const interventions = this.identifyInterventions(graph, sinkNodeId, inputs, outputs);
    
    // 6. Project time-to-impact
    const projection = this.trajectoryProjector.project(
      history,
      this.getCriticalThreshold(sinkType),
      this.getWarningThreshold(sinkType)
    );
    
    return {
      sinkId: sinkNodeId,
      sinkType: sinkType as any,
      description: this.describeSink(sinkNodeId, sinkType, graph),
      currentValue: history[history.length - 1]?.value ?? 0,
      threshold: this.getCriticalThreshold(sinkType),
      inputTopology: inputs.map(e => e.source),
      outputTopology: outputs.map(e => e.target),
      growthPattern,
      growthRate,
      blastRadius,
      interventionPoints: interventions,
      timeToImpact: projection.warningIntersection ? 
        projection.warningIntersection - Date.now() : Infinity,
      timeToCritical: projection.ceilingIntersection ? 
        projection.ceilingIntersection - Date.now() : Infinity,
      severity: this.classifySeverity(projection, growthPattern),
      confidence: projection.confidence
    };
  }

  /**
   * GROWTH PATTERN CLASSIFICATION
   * 
   * Algorithm:
   * 1. Calculate successive growth ratios: r[i] = v[i+1] / v[i]
   * 2. If all r ≈ 1.0 (±0.1): BOUNDED (stable)
   * 3. If r ≈ constant > 1.0: LINEAR growth
   * 4. If r is increasing: EXPONENTIAL growth
   * 5. If r varies with periodicity: EPISODIC
   * 
   * This matters because intervention strategy differs:
   * - Linear: Can be managed with periodic cleanup
   * - Exponential: Requires structural intervention NOW
   * - Bounded: Monitor but don't panic
   * - Episodic: Plan around spikes, don't over-engineer
   */
  private classifyGrowth(history: { timestamp: number; value: number }[]): 
    'linear' | 'exponential' | 'bounded' | 'episodic' {
    
    if (history.length < 4) return 'bounded';
    
    const ratios = [];
    for (let i = 1; i < history.length; i++) {
      const ratio = history[i].value / Math.max(history[i-1].value, 0.001);
      ratios.push(ratio);
    }
    
    const meanRatio = ratios.reduce((s, r) => s + r, 0) / ratios.length;
    const variance = ratios.reduce((s, r) => s + (r - meanRatio) ** 2, 0) / ratios.length;
    
    // Check for periodicity (episodic)
    if (variance > 0.5 && this.hasPeriodicity(ratios)) {
      return 'episodic';
    }
    
    // Check if bounded
    if (Math.abs(meanRatio - 1.0) < 0.1) {
      return 'bounded';
    }
    
    // Check if exponential (ratio increasing)
    const ratioTrend = this.fitLinear(ratios.map((r, i) => ({ x: i, y: r })));
    if (ratioTrend.slope > 0.05) {
      return 'exponential';
    }
    
    return 'linear';
  }

  /**
   * BLAST RADIUS CALCULATION
   * 
   * BFS from the sink node through the dependency graph.
   * 
   * Direct: Nodes within 1 hop
   * Indirect: Nodes within 2 hops
   * Cascading: Nodes within 3+ hops
   * 
   * Weighted by edge strength — strong dependencies
   * are more likely to cascade failures.
   */
  private calculateBlastRadius(
    graph: KnowledgeGraph,
    sinkId: string,
    outputs: Edge[]
  ): { direct: string[]; indirect: string[]; cascading: string[] } {
    
    const direct: string[] = [];
    const indirect: string[] = [];
    const cascading: string[] = [];
    
    const visited = new Set<string>();
    const queue: { nodeId: string; depth: number }[] = [{ nodeId: sinkId, depth: 0 }];
    
    while (queue.length > 0) {
      const { nodeId, depth } = queue.shift()!;
      if (visited.has(nodeId)) continue;
      visited.add(nodeId);
      
      const outEdges = graph.getOutgoingEdges(nodeId, { depth: 1 });
      
      for (const edge of outEdges) {
        if (depth === 0) direct.push(edge.target);
        else if (depth === 1) indirect.push(edge.target);
        else cascading.push(edge.target);
        
        if (depth < 3) {
          queue.push({ nodeId: edge.target, depth: depth + 1 });
        }
      }
    }
    
    return { direct, indirect, cascading };
  }

  /**
   * INTERVENTION POINT IDENTIFICATION
   * 
   * For each detected sink, identify WHERE we can intervene:
   * 
   * UPSTREAM: Reduce what feeds into the sink
   *   - If a file is growing too large: Split it, reduce imports
   *   - If an agent is overloaded: Redistribute tasks
   *   - If a skill is failing: Evolve it (Phase 5)
   * 
   * AT THE SINK: Reduce the sink's consumption
   *   - If budget draining: Apply stricter cost gates
   *   - If dependency growing: Refactor to reduce coupling
   *   - If scope creeping: Enforce scope boundaries
   * 
   * DOWNSTREAM: Mitigate effects
   *   - Add caching to reduce repeated work
   *   - Add monitoring to catch issues earlier
   *   - Add fallbacks for when the sink fails
   * 
   * STRUCTURAL: Redesign to eliminate
   *   - Change architecture to remove the bottleneck
   *   - Split a monolith into services
   *   - Replace a dependency with a better alternative
   */
  private identifyInterventions(
    graph: KnowledgeGraph,
    sinkId: string,
    inputs: Edge[],
    outputs: Edge[]
  ): Intervention[] {
    
    const interventions: Intervention[] = [];
    
    // Upstream interventions
    for (const input of inputs) {
      const sourceNode = graph.getNode(input.source);
      if (sourceNode?.type === 'file' && sourceNode.lineCount > 1000) {
        interventions.push({
          action: `Split ${input.source} into smaller modules`,
          target: input.source,
          cost: 4,  // hours
          effectiveness: 0.6,
          urgency: 'this_week'
        });
      }
      if (sourceNode?.type === 'agent' && sourceNode.workloadScore > 0.8) {
        interventions.push({
          action: `Redistribute tasks from ${input.source} to underutilized agents`,
          target: input.source,
          cost: 1,
          effectiveness: 0.4,
          urgency: 'immediate'
        });
      }
    }
    
    // At-the-sink interventions
    const sinkNode = graph.getNode(sinkId);
    if (sinkNode?.type === 'file' && sinkNode.importCount > 20) {
      interventions.push({
        action: `Reduce coupling: ${sinkId} has ${sinkNode.importCount} importers`,
        target: sinkId,
        cost: 8,
        effectiveness: 0.7,
        urgency: 'this_month'
      });
    }
    
    // Structural interventions
    if (inputs.length > 10 && outputs.length > 10) {
      interventions.push({
        action: `Architectural refactor: ${sinkId} is a bottleneck node`,
        target: sinkId,
        cost: 16,
        effectiveness: 0.9,
        urgency: 'planned'
      });
    }
    
    // Sort by (effectiveness / cost) descending
    return interventions.sort((a, b) => 
      (b.effectiveness / b.cost) - (a.effectiveness / a.cost)
    );
  }
}
```

### 4. Anomaly Detector

**Purpose:** Detect sudden, unexpected changes that don't fit gradual divergence patterns.

```typescript
/**
 * ANOMALY DETECTION ALGORITHMS
 * 
 * 1. STATISTICAL OUTLIER (Z-score)
 *    - For each metric, maintain rolling mean and std dev
 *    - Flag when |value - mean| > 3 × std_dev
 *    - Use for: sudden cost spikes, error rate jumps
 * 
 * 2. PATTERN BREAK
 *    - Maintain expected pattern (e.g., "cost per session ≈ $0.50")
 *    - Flag when actual breaks pattern for 3+ consecutive observations
 *    - Use for: behavioral changes, workflow pattern shifts
 * 
 * 3. SUDDEN CHANGE (CUSUM)
 *    - Cumulative sum control chart
 *    - Detects small, sustained shifts that Z-score misses
 *    - Use for: gradual degradation that accelerates
 * 
 * 4. CORRELATION BREAK
 *    - Track correlations between metrics (e.g., "tokens ∝ task count")
 *    - Flag when correlation breaks
 *    - Use for: efficiency changes, model behavior shifts
 */
```

### 5. Drift Detector

**Purpose:** Detect slow, cumulative changes that individually seem fine but collectively represent a significant shift.

```typescript
/**
 * DRIFT TYPES:
 * 
 * 1. Team Drift
 *    Project evolved (new frameworks, new requirements)
 *    but team composition stayed the same.
 *    Detection: Re-run scanner, compare to current team.
 * 
 * 2. Skill Drift
 *    Skill was effective 3 months ago but effectiveness
 *    has slowly declined as the project changed.
 *    Detection: Rolling success rate trend analysis.
 * 
 * 3. Scope Drift
 *    Project scope has expanded beyond original boundaries
 *    without corresponding team/budget expansion.
 *    Detection: File count, module count, dependency count trends.
 * 
 * 4. Debt Drift
 *    Technical debt accumulating faster than being paid down.
 *    Detection: Ratio of new code to refactored code over time.
 * 
 * 5. Cost Drift
 *    Average cost per task slowly increasing.
 *    Detection: Rolling average cost trend.
 */
```

## THE EARLY WARNING SYSTEM

### Warning Event Schema

```typescript
interface WarningEvent {
  id: string;
  timestamp: number;
  
  // Classification
  type: 'resource_sink' | 'divergence' | 'drift' | 'anomaly' | 'trajectory';
  category: 'budget' | 'team' | 'code' | 'roadmap' | 'skill' | 'dependency' | 'workflow';
  severity: 'informational' | 'warning' | 'critical';
  confidence: number;            // 0-1
  
  // What
  description: string;           // Human-readable summary
  affectedNodes: string[];       // Knowledge graph node IDs
  
  // Trajectory
  currentValue: number;
  projectedValue: number;        // If unaddressed
  timeToWarning: number;         // ms until warning threshold
  timeToCritical: number;        // ms until critical threshold
  
  // Shape (for resource sinks)
  topology?: ResourceSinkAnalysis;
  
  // Response
  interventionOptions: Intervention[];
  recommendedAction: string;
  autoRemediable: boolean;       // Can the system fix this itself?
  
  // Lifecycle
  status: 'active' | 'acknowledged' | 'resolved' | 'dismissed';
  firstDetected: number;
  lastUpdated: number;
  resolvedAt?: number;
  resolution?: string;
}
```

### Warning Delivery

Warnings are delivered through multiple channels:

1. **Dashboard** (50k foot view) — always visible
2. **SessionStart hook** — inject top 3 warnings into agent context
3. **CLI notification** — `⚠️ [WARNING] Budget trajectory hits ceiling in 4 days`
4. **Agent prompt injection** — "You have an active warning about X. Consider Y."
5. **PR annotation** — If a PR touches a warned-about area, annotate it

### Warning Suppression

To prevent alert fatigue:
- **Deduplication:** Same warning type + same node = one warning
- **Cooldown:** Don't re-warn about the same issue within 24 hours
- **Escalation:** Informational → Warning → Critical (only escalate if worsening)
- **Batching:** Group related warnings into a single digest
- **Auto-dismiss:** If the underlying metric returns to normal, auto-resolve

## THE PHILOSOPHICAL SHIFT

The original blueprint asked: **"What happened and how do we respond?"**

The Foresight Engine asks: **"What is happening, what will happen, and what should we do about it before it happens?"**

This is the difference between a **thermostat** (reactive: temperature drops, heater turns on) and a **weather forecasting system** (proactive: cold front approaching, prepare now).

ZCode with the Foresight Engine doesn't just execute tasks. It **understands the shape of the system it operates within**, anticipates where problems will emerge, and recommends interventions before the problems materialize.

This is what "50,000 foot view at all times" means: not just seeing the current state, but seeing the **trajectory** of the current state, the **topology** of emerging problems, and the **intervention space** available to address them.
